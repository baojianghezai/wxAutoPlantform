# 微信自动化平台 · 项目总文档

> 面向：平台全貌、架构、目录结构、启动方式、端到端数据流。
> 配套文档：`docs/01-n8n设计.md`、`docs/02-Flask服务文档.md`、`docs/03-模板分类器文档.md`。

## 1. 平台定位

一个「**公众号招聘内容自动化生产线**」：定时抓取招聘信源 → 合并成统一文章 feed → 运营人工在网页上挑选文章与模板 → 大模型改写 → 自动渲染模板并推送到微信公众号草稿箱。

全程由 **n8n 编排**，本地 **Flask 服务** 作为 n8n 与本地脚本/前端之间的桥接层。

## 2. 系统组成

| 组件 | 位置 | 角色 |
|------|------|------|
| n8n | 远端/本地编排 | 定时触发、Wait 节点挂起等待、调钉钉通知、大模型改写、调 `/api/publish` |
| Flask 桥接服务 | `自动化脚本合集/server/app.py`（端口 5001） | 提供 7 个 API、托管前端产物、驱动爬虫 pipeline |
| 爬虫 pipeline | `server/pipeline.py` | 顺序跑 task1_index → 16 方向爬虫 → merge → adapter → combine |
| 前端 wxcheck | `wxcheck/`（Vue 3 + Vite + TS） | 文章卡片列表、模板选择、推送确认 |
| 渲染器 | `renderers/__init__.py` | 把大模型结构化 JSON 渲染成公众号 HTML（全内联样式） |
| 模板选择器 | `templates/selector.py` | 按 `content_type` 选模板 + 渲染器 |
| 发布模块 | `publish/`（wechat_draft.py） | 清洗 HTML、传图、推送草稿箱（cgi-bin/draft/add） |

## 4. 端口规划

| 端口 | 用途 |
|------|------|
| 5001 | Flask 主服务（API + 前端托管）；5000 已被目标机 Docker RSS 占用 |
| 5173 | 前端 vite dev（改前端时用，开发模式经 `/api` 代理到 5001） |
| 9000 | Mock n8n 接收器（调试用，正式接入后关掉） |
| 192.168.10.240:5000 | RSS 聚合器（config.json `rss_url`） |

## 5. 启动方式

```bat
双击 启动服务.bat
```

脚本做的事（详见文件内注释）：

1. 首次运行自动创建 `自动化脚本合集/.venv` 并 `pip install -r server/requirements.txt`（flask / flask-cors / requests）；`.venv` 从别机拷来失效时会自动重建。
2. 启动 `server\app.py`（`WxAuto-5001` 窗口，端口 5001）。
3. 探测系统 Python 是否可 `import crawl4ai`（pipeline 依赖），缺失则告警。
4. 打开浏览器 `http://localhost:5001`。

> 可选：`启动服务.bat` 中有两个被注释的启动项 —— Mock 接收器（9000）与前端 dev（5173），按需取消注释。

## 6. 端到端数据流

```
n8n 定时触发
 → ① POST /api/waitUrl           登记 Wait 节点回调 URL（存 server/state.json）
 → ② GET  /api/run               触发爬虫 pipeline（202 立即返回，后台跑，防重入）
 → (n8n Wait 节点挂起)
 → Flask pipeline 结束 → POST {waitUrl}   唤醒 n8n（payload: code/msg/stats）
 → ③ n8n 调钉钉 API 发审核通知
 → 运营打开前端 5001 选文章+模板
 → 前端 POST /api/submit          Flask 抓原文 HTML → POST {waitUrl}（带 html）
 → ④ n8n 收 HTML → 去标签 → 大模型改写结构化 JSON
 → ⑤ n8n POST /api/publish        渲染模板 → 推微信草稿箱，返回 media_id
```

> 两个 Wait 节点先后挂起时，各自挂起后都要 POST `/api/waitUrl` 覆盖登记自己的 URL；`state["waitUrl"]` 始终等于"最近挂起的 Wait 节点"的地址（详见 `docs/01-n8n设计.md`）。

## 7. 数据契约（文章统一格式）

`crawl4ai/scripts/shandong_official/shandong_output/unified_articles.json` 由 `combine.py` 合并产出，前端与 Flask 只认这一个 feed：

```json
{
  "schema_version": "1.0",
  "source_system": "combined",
  "scope": "all",
  "generated_at": "2026-08-01T00:00:00+08:00",
  "stats": {"web_total": 40, "wechat_total": 34, "total": 74},
  "articles": [
    {
      "id": "web_8201fbd9",          // web 用 web_xxx，wechat 用 A01
      "title": "标题",
      "source": "来源名",
      "source_type": "web | wechat",
      "direction": "方向名（wechat 为空）",
      "category": "分类",
      "published_at": "2026-07-29",
      "url": "原文链接",
      "summary": "摘要",
      "thumbnail": "缩略图 URL",
      "extra": { ... }
    }
  ]
}
```

- web 侧来源：`信源文章汇总页_综合.json`（权威），缺失时回退各 `子方向*.json`。
- wechat 侧来源：`review/index.json`（task1_index 产出），由 `adapter_task1.py` 转换（保持字段与 web 一致）。

## 8. 配置项（config.json）

| 键 | 说明 |
|----|------|
| `rss_url` / `days` | 公众号 RSS 聚合器地址与回看窗口天数 |
| `accounts.gov` / `media` | 政府/媒体公众号名单 |
| `cross_account_aliases` | 跨账号别名合并 |
| `known_companies` | 已知企业名单 |
| `wechat.appid` / `secret` | 公众号凭证（环境变量 `WECHAT_APPID` / `WECHAT_SECRET` 优先） |
| `task2.tail_images_dir` | 尾图目录（默认 `tail_images`） |
| `max_images` / `filter_expired` | 抓取图片数上限 / 是否过滤已过期岗位 |

## 9. 关键运维注意

- 推草稿箱要求运行机公网 IP 在公众号后台 IP 白名单内，否则 `errcode 40164`。
- `/api/run` 有防重入锁，运行中重复调用返回 `code:1 "pipeline already running"`。
- task1_index 产出 0 条时（RSS 不可达）会自动用 `review/index.backup.json` 还原，避免清空公众号信源。
- 单方向爬虫失败不中断整个 pipeline，记入 `failed_directions`。
