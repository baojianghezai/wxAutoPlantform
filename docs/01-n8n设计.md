# n8n 设计文档

> 目标：在 n8n 中搭建「招聘内容自动化」工作流，本地 Flask（`自动化脚本合集/server/app.py`，端口 5001）作为桥接。
> 本平台 n8n 官方介绍与对接说明原文见 `自动化脚本合集/server/n8n对接说明.md`。

## 1. 工作流总览（线性流程）

```
[定时触发 / Schedule]
   │
   ▼
[① HTTP Request: POST /api/waitUrl]       登记 Wait① 回调 URL
   │
   ▼
[② HTTP Request: GET /api/run]            触发爬虫 pipeline（202 立即返回）
   │
   ▼
[Wait 节点 ①]                              挂起，等待 Flask 回调
   │  ◄── Flask pipeline 结束 POST {URL①}（code/msg/stats）
   ▼
[③ 钉钉通知]                                发审核通知给运营
   │
   ▼
[Wait 节点 ②]                              挂起，等待运营在前端选文
   │  ① 运营打开 http://localhost:5001
   │  ② 前端 POST /api/submit → Flask 抓原文 HTML
   │  ③ Flask POST {URL②}（带 html）── 唤醒本节点
   ▼
[④ 大模型改写]                              收 HTML → 去标签 → 输出结构化 JSON
   │
   ▼
[⑤ HTTP Request: POST /api/publish]       渲染模板 → 推草稿箱 → 返回 media_id
   │
   ▼
[结束]
```

## 2. 核心机制：Wait 节点的 URL 登记

n8n 中每个 Wait 节点挂起时会生成**各自的** resume URL（`https://<n8n>/webhook-waiting/<uuid>`），
唤醒方式是对该 URL 发 POST。

**设计要点**：由于是线性流程且两个 Wait 节点先后挂起，Flask 的 `state.json` 只用一个键即可：

```
state["waitUrl"] = "最近一次挂起的 Wait 节点的回调 URL"
```

- Wait① 挂起 → n8n 先 `POST /api/waitUrl {"url": URL①}` 登记
- Flask pipeline 结束 → POST URL① → 唤醒 Wait①
- Wait② 挂起 → n8n **再次** `POST /api/waitUrl {"url": URL②}`，覆盖为 URL②
- 前端 `/api/submit` → Flask POST `state["waitUrl"]`（此时是 URL②）→ 唤醒 Wait②

**约束/注意**：
- 两个 Wait 节点之间不要再触发并发的第二次 `/api/run`，否则 pipeline 结束回调会打到新登记的 URL 上。
- Wait② 的登记必须发生在运营 `POST /api/submit` **之前**（线性流程中天然满足，但要注意调度顺序）。

## 3. 节点契约

### ① POST /api/waitUrl

请求：
```json
{ "url": "https://<n8n>/webhook-waiting/<uuid>" }
```
响应：`{"code": 0}`；URL 落盘 `server/state.json`，重启不丢。
`url` 缺失返回 `400 {"code":1,"msg":"missing url"}`。

### ② GET /api/run

- 成功（立即返回）：`202 {"code":0,"msg":"pipeline started"}`
- 运行中重复调用：`{"code":1,"msg":"pipeline already running"}`

**爬虫结束后 Flask 回调 Wait① 的 payload：**
```json
{
  "code": 0,
  "msg": "pipeline done",
  "stats": {"web_total": 40, "wechat_total": 34, "total": 74, "failed_directions": []}
}
```

### ③ 钉钉审核通知

n8n 调用钉钉 API 通知运营去前端选文。无固定 payload 契约，通知内容建议带上：
本次候选总数、失败方向数、前端入口地址 `http://localhost:5001`。

### ④ Wait② 收到的数据（Flask → n8n，前端 /api/submit 触发）

```json
{
  "article_id": "web_8201fbd9",
  "title": "文章标题",
  "url": "原文链接",
  "html": "原文正文 HTML（已提取正文区域，微信为 js_content，其他站为正文容器）",
  "template_id": "zhaopin1"
}
```

> `template_id` 是运营在前端选的模板 id（可选字段；不传则大模型/分类器按 content_type 定）。

### ⑤ 大模型改写（prompt 约束）

输入：上一步的 `html`（先去掉标签）。**要求大模型输出严格 JSON**：

```json
{
  "content_type": "job_list | solar_term | 其他",
  "template_id": "可选，显式指定模板（zhaopin1/zhaopin2/xiaoshu）",
  "title": "公众号文章标题",
  "digest": "摘要，可选",
  "sections": [
    {"type": "hero", "title": "...", "subtitle": "..."},
    {"type": "cards", "items": [{"title": "...", "fields": {"键": "值"}, "tags": ["..."], "description": "..."}]},
    {"type": "key_points", "title": "...", "points": ["...", "..."]},
    {"type": "paragraph", "heading": "可选", "text": "..."},
    {"type": "image", "url": "...", "caption": "可选"}
  ]
}
```

- `content_type` 决定默认模板与渲染器：`job_list`（招聘岗位）、`solar_term`（节气时令），其他值走兜底渲染。
- `sections.type` 目前支持：`hero` / `cards` / `key_points` / `paragraph` / `image`，顺序任意。
- 生成后原样 POST 到 `/api/publish` 即可。

### ⑥ POST /api/publish

请求体 = 大模型输出的结构化 JSON（原样 POST）。

- 成功：`{"code":0,"media_id":"..."}`
- 失败：`{"code":1,"msg":"..."}`（HTTP 500，见 `docs/02-Flask服务文档.md`）

**注意**：推草稿箱要求运行机器的公网 IP 在公众号后台的 IP 白名单内，否则报 `errcode 40164`。
凭证优先环境变量 `WECHAT_APPID` / `WECHAT_SECRET`，回退 `config.json`。

## 4. 调试手段

- 本地 Mock 接收器：`python server/mock_receiver.py`（监听 9000，把 POST 记到 `server/mock_received.jsonl`），可用来验证 `/api/run`、`/api/submit` 的回调 payload。
- mock 样例：`server/mock_llm_input.json`（前端提交后 Flask 回调 waitUrl 的 payload）、`server/mock_llm_output.json`（大模型应输出的结构化 JSON 参考）。

## 5. 建议的 n8n 节点清单

| 序号 | 节点类型 | 配置要点 |
|------|----------|----------|
| 1 | Schedule Trigger | 定时执行（如每天上午） |
| 2 | HTTP Request | POST `http://localhost:5001/api/waitUrl`，body 填 Wait① 的 URL |
| 3 | HTTP Request | GET `http://localhost:5001/api/run` |
| 4 | Wait | Resume：Webhook；等 Flask 回调 |
| 5 | 钉钉（HTTP Request） | 发审核通知 |
| 6 | Wait | Resume：Webhook；挂起等运营选文 |
| 7 | HTTP Request 先 POST `/api/waitUrl` | 登记 Wait② 的 URL（覆盖） |
| 8 | HTTP Request | POST `/api/publish`，body = 大模型输出 JSON |
