# 爬虫数据接口文档（web_crawler）

> 版本：schema_version 1.0
> 适用脚本：`shandong_official/shandong_official_crawler.py`（综合爬取全部 52 个信源）
> 读者：前端对接人员（审查页 /api/check）

---

## 1. 概述

本爬虫负责按内容方向定向抓取信源网站文章，输出**统一契约 JSON**，供前端审查页读取并展示。前端**只需遍历 `articles` 数组**即可渲染，无需关心抓取细节。

| 项 | 说明 |
|----|------|
| 调用方式 | CLI（由本地 Flask 服务在收到 n8n `GET /api/run` 后触发执行） |
| 输出物 | 每个方向一个 JSON + 一个综合 JSON |
| 契约版本 | `schema_version`: `1.0` |
| 数据系统标识 | `source_system`: `web_crawler` |

---

## 2. 调用方式（CLI）

### 2.1 综合爬取

```bash
python shandong_official_crawler.py \
  --config sources_config.json \
  --output shandong_output/山东官方招聘_综合.html \
  --json   shandong_output/山东官方招聘_综合.json
```

| 参数 | 必填 | 说明 |
|------|------|------|
| `--config` | 是 | 方向配置文件（JSON），内含信源列表与爬取规则 |
| `--output` | 否 | 人工浏览用的 HTML 汇总页路径，前端可不读取 |
| `--json` | 是 | **契约 JSON 输出路径，前端读取的就是该文件** |

### 2.2 人工浏览汇总

```bash
python shandong_official_crawler.py
```

输出：`shandong_output/山东官方招聘_综合.json` + `山东官方招聘_综合.html`（scope=`all`，含全部信源）。

## 3. 返回格式

### 3.1 综合（`crawler.py --json`）

```json
{
  "schema_version": "1.0",
  "source_system": "web_crawler",
  "scope": "direction",
  "generated_at": "2026-07-30T14:38:00+08:00",
  "direction": {
    "code": "01",
    "name": "劳动法规解读",
    "category": "政策法规"
  },
  "stats": {
    "source_total": 3,
    "source_ok": 1,
    "article_total": 10
  },
  "articles": [ /* 见 §4 */ ]
}
```

### 3.2 综合（`山东官方招聘_综合.json`）

```json
{
  "schema_version": "1.0",
  "source_system": "web_crawler",
  "scope": "all",
  "generated_at": "2026-07-30T14:38:00+08:00",
  "directions": [
    {"code": "01", "name": "劳动法规解读", "category": "政策法规", "article_count": 10}
  ],
  "stats": {
    "direction_total": 15,
    "article_total": 40
  },
  "articles": [ /* 结构同 §4，已按 published_at 降序 */ ]
}
```

> **重要**：两种输出的 `articles` 字段结构**完全一致**，前端统一遍历 `articles` 即可，无需区分 `scope`。`scope=all` 时额外提供 `directions`（方向汇总）与 `stats.direction_total`。

### 3.3 顶层字段含义

| 字段 | 类型 | 说明 |
|------|------|------|
| `schema_version` | string | 契约版本，当前 `1.0` |
| `source_system` | string | 固定 `web_crawler` |
| `scope` | string | `direction`（综合）/ `all`（综合） |
| `generated_at` | string | 生成时间，ISO8601（含时区 +08:00） |
| `direction` | object | 综合时存在：`{code, name, category}` |
| `directions` | array | 综合时存在：各方向 `{code, name, category, article_count}` |
| `stats` | object | 统计：`source_total`/`source_ok`/`article_total`（综合另含 `direction_total`） |
| `articles` | array | **文章列表，前端主数据** |

---

## 4. `articles` 元素字段含义

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `id` | string | 是 | 文章唯一 ID，由原文 URL 的 MD5 前 8 位生成，前缀 `web_`。**同一链接多次爬取 ID 不变**，用于前端去重与"选定回传" |
| `title` | string | 是 | 文章标题 |
| `source` | string | 是 | 信源网站名称（如"最高人民法院"） |
| `source_type` | string | 是 | 固定 `web`（与公众号来源 `wechat` 区分，见 §6） |
| `direction` | string | 是 | 内容方向名（如"劳动法规解读"） |
| `category` | string | 是 | 内容板块：政策法规 / 科技动态 / 行业动态 / 原创实操 |
| `published_at` | string | 是 | 发布日期，已归一化为 `YYYY-MM-DD`；无法识别时为 `""` |
| `url` | string | 是 | 原文链接，前端"查看原文"按钮 `window.open(url)` |
| `summary` | string | 否 | 摘要，web 来源当前为空，预留扩展；wechat 来源含正文摘要 |
| `thumbnail` | string | 否 | 缩略图 URL；wechat 来源为公众号首图（已还原 `&amp;`→`&`），web 来源暂空 |
| `extra` | object | 否 | **仅 wechat 来源存在**：`{accounts, deadline, companies, attachments, image_count, is_media, note}`，保留 task1 原始字段供 Task2 回查；web 来源此字段不存在 |

**单条示例（web 来源）：**
```json
{
  "id": "web_7e567712",
  "title": "XX劳动争议典型案例发布 - 中华人民共和国最高人民法院",
  "source": "最高人民法院",
  "source_type": "web",
  "direction": "劳动法规解读",
  "category": "政策法规",
  "published_at": "2026-07-28",
  "url": "https://www.court.gov.cn/zixun/xiangqing/507221.html",
  "summary": "",
  "thumbnail": ""
}
```

**单条示例（wechat 来源，由 adapter_task1 转换）：**
```json
{
  "id": "A01",
  "title": "2026年青岛华通集团招聘工作人员！正在报名中！",
  "source": "青岛市国企招聘",
  "source_type": "wechat",
  "direction": "",
  "category": "公众号招聘",
  "published_at": "2026-07-28",
  "url": "https://mp.weixin.qq.com/s/75l8MDk4xEjs9XawMtYfPg",
  "summary": "2026年青岛国企招聘 一、招聘需求 法务资深经理1名……",
  "thumbnail": "https://mmbiz.qpic.cn/mmbiz_png/.../640?wx_fmt=png",
  "extra": {
    "accounts": ["青岛市国企招聘"],
    "deadline": "2026-08-31 00:00",
    "companies": ["年青岛华通集团"],
    "attachments": [],
    "image_count": 5,
    "is_media": false,
    "note": ""
  }
}
```

> **注意**：wechat 来源 `direction` 固定为 `""`（task1 无方向分类），`category` 统一为 `"公众号招聘"`；前端按 `source_type` 区分来源样式即可。

## 5. 前端对接要点

1. **展示列**：标题 `title`、发布时间 `published_at`、来源 `source`、方向 `direction`、板块 `category`。
2. **查看原文**：`<a :href="article.url" target="_blank">查看原文</a>`。
3. **选定进入下一步**：将选中条的 `id` 回传后端（由 Flask 负责 POST 到 n8n wait 节点）；后端可据 `id` 在 `articles` 中定位原文 `url`。
4. **排序**：综合 JSON 已按 `published_at` 降序；综合为抓取顺序，前端可自排序。
5. **分组/筛选**：可按 `direction`、`category`、`source` 维度分组或筛选。
6. **空态处理**：`articles` 为空数组时展示"暂无文章"。

## 6. 与公众号来源（task1_index）的统一【已实现】

前端还会消费 `task1_index` 产出的公众号文章。二者**共用同一 `articles` 契约**，已实现非侵入式适配（不修改 `task1_index.py`，避免破坏下游 Task2）：

| 维度 | web_crawler（本爬虫） | task1_index（公众号，经 adapter 转换） |
|------|----------------------|----------------------------------------|
| 脚本 | `crawler.py` / `merge_summary.py` | `adapter_task1.py` → 读 `review/index.json` |
| `source_type` | `web` | `wechat` |
| `id` | `web_<md5前8位>` | `A01` 等（保留 task1 去重编号，供 Task2 回查） |
| `direction` | 内容方向名 | `""`（task1 无方向分类） |
| `category` | 政策法规/科技动态/… | `公众号招聘` |
| `published_at` | 抓取页日期归一化 | RFC2822 `pubDate` 解析为 `YYYY-MM-DD` |
| `extra` | 无 | 含 `accounts/deadline/companies/attachments/is_media/note` |

### 6.1 合并为单一 feed（前端推荐读取入口）

`combine.py` 把 web + wechat 两套数据合并为**一个** `articles` 数组，按 `published_at` 降序、按 `id` 去重：

```bash
python combine.py
# 输出：shandong_output/unified_articles.json
```

```json
{
  "schema_version": "1.0",
  "source_system": "combined",
  "scope": "all",
  "generated_at": "2026-07-30T15:10:00+08:00",
  "stats": { "web_total": 40, "wechat_total": 34, "total": 74 },
  "articles": [ /* web + wechat 混合，结构同 §4 */ ]
}
```

> **前端 / Flask 接入层只需读取 `unified_articles.json` 这一个文件**，无需分别处理 web 与 wechat。其中 `web_total` / `wechat_total` 反映两侧各自数量，便于对账。

### 6.2 单独查看公众号侧（可选）

```bash
python adapter_task1.py
# 输出：shandong_output/unified_wechat.json（仅 wechat 来源）
```

## 7. 错误与边界

- **单信源失败**：该信源 `articles` 为空，**不影响其他信源**；`stats.source_ok` 反映成功数。
- **`published_at` 为 `""`**：页面未提取到日期，前端应显示"未知"而非报错。
- **全部 0 篇**：`articles` 为空数组，前端展示空态即可。
- **反爬/超时**：常见现象（如人社部、司法部），属预期内，无需告警。
